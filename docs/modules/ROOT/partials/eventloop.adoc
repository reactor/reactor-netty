=== Event Loop Group

By default `Reactor Netty` uses an "`Event Loop Group`", where the number of the worker threads equals the number of
processors available to the runtime on initialization (but with a minimum value of 4). This "`Event Loop Group`" is shared between all servers and clients in one JVM.
When you need a different configuration, you can use one of the {javadoc}/reactor/netty/resources/LoopResources.html[`LoopResources`]`#create` methods.

==== Native Transports

`reactor-netty-core` brings the native `Epoll` transport only for `linux-x86_64`.
On other platforms, Reactor Netty falls back to the `NIO` transport.
The fallback is reported only when the logger `reactor.netty.resources` level is set to `DEBUG` (`Default Epoll support : false`).

To use a native transport on another platform, add the native library for that platform,
using the same `Netty` version as the one Reactor Netty depends on.
For example, for `Linux` on `aarch64`, add the following Maven dependency:

[source,xml]
----
<dependencies>
    <dependency>
        <groupId>io.netty</groupId>
        <artifactId>netty-transport-native-epoll</artifactId>
        <version>${netty.version}</version> <1>
        <classifier>linux-aarch_64</classifier>
        <scope>runtime</scope>
    </dependency>
</dependencies>
----
<1> The version is required. Use the `Netty` version that Reactor Netty depends on.

Or the following Gradle dependency:

[source,groovy]
----
dependencies {
    runtimeOnly 'io.netty:netty-transport-native-epoll::linux-aarch_64' <1>
}
----
<1> The version can be omitted. It is resolved to the `Netty` version that Reactor Netty brings transitively.

For `macOS`, add `io.netty:netty-transport-native-kqueue` with the `osx-x86_64` or `osx-aarch_64` classifier.

For `Linux`, you can also use the `io_uring` transport. It requires Java 11 or later.
Add `io.netty:netty-transport-native-io_uring` with the `linux-x86_64` or `linux-aarch_64` classifier.
When `io_uring` is available, Reactor Netty uses it instead of `Epoll`.

For `KQueue` and `io_uring`, the version is required for both Maven and Gradle, because `reactor-netty-core` does not bring them transitively.

==== Disposing Event Loop Group

- If you use the default `Event Loop Group` provided by Reactor Netty, invoke
{javadoc}/reactor/netty/http/HttpResources.html[`HttpResources`]`#disposeLoopsAndConnections`/`#disposeLoopsAndConnectionsLater` method.

NOTE: Disposing `HttpResources` means that every server/client that is using it, will not be able to use it anymore!

- If you use custom `LoopResources`, invoke {javadoc}/reactor/netty/resources/LoopResources.html[`LoopResources`]`#dispose`/`#disposeLater` method.

NOTE: Disposing the custom `LoopResources` means that every server/client that is configured to use it, will not be able to use it anymore!
